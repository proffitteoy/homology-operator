# 产品测试输入与来源

测试样本只用于独立正确性与兼容性验证，不进入生产计算路径。
生产输出来自输入窗口与合法 P；oracle 的最短类质量或 PH 结果不能填充产品结果。

## 单尺度与过滤窗口

[reference.json](../tests/fixtures/reference.json) 保存 23 份带基 H0–H3 链窗口，
覆盖空空间、零同调、基置换、重复尺度、人工正权与实际欧氏边长/面积/体积。
[独立标准库 oracle](../tests/oracle/reference.py) 使用整数 XOR、列组合和 Fraction，
不导入生产消元、solver 或算子。窗口以显式 nrows/ncols/rows 保存矩阵，包括 0×n 和 n×0。
带序基使用唯一字符串，精确权保存 numerator/denominator，浮点权保存 JSON 数值。

迁移来源固定为 [homology-operator-lab](https://github.com/proffitteoy/homology-operator-lab/tree/6143729669902ee875b211b58085e954c76cdf88)
的 `6143729669902ee875b211b58085e954c76cdf88`。每份 fixture 的 source 保留路径、
原始源码 hash、迁移步骤、参数及明确的本地补充。

## Birth-pair cycle inputs

[optimal_cycles.json](../tests/fixtures/optimal_cycles.json) records three ordered
simplicial inputs, their birth edges, unit costs and results from the unchanged
`search` source functions in HomCloud 5.4.0. Its provenance pins the official
source archive SHA-256 and `homcloud/optimal_one_cycle.py` byte hash. The package
is not a runtime dependency; native/public Pair integration was not executed.
Triangle and already-filled-face cases have identical feasible sets at birth.
The older-class counterexample deliberately compares different objectives: a
3-edge birth-only optimum and the 4-edge chosen historical class. Equal scale
endpoints do not identify features; the insertion order and original vertex IDs
are retained. [Query tests](../tests/test_optimal_cycle.py) independently enumerate
all chains on the small windows and separately cover exact lengths, ties,
disconnected birth histories, source identity and rank/budget limits. Source
replay instructions and dependency boundaries are in
[validation](en/VALIDATION.md#birth-pair-cycle-checks).

## Fixed-boundary filling inputs

[test_filling.py](../tests/test_filling.py) generates local, hand-derived inputs;
no research fixture is migrated. H1 uses all triangle faces on four planar
vertices `(0,0), (2,0), (2,2), (0,2)`, with determinant areas 2 m^2 each.
H2 uses tetrahedra on `(0,0,0), (6,0,0), (0,6,0), (0,0,6), (1,1,1)`, with
exact determinant volumes `(36,6,6,6,18)` m^3 in combination order.
The tests build actual face incidences, enumerate all upper chains independently,
and compare minimum mass and ties. Abstract costs, counting, invalid sources,
nonboundaries, zero chains, budgets, cancellation and tampered certificates are
tested separately. These finite checks establish neither general performance
nor correctness of caller-declared real-world measurements.

## 显式单形与外部 oracle

[simplicial.json](../tests/fixtures/simplicial.json)保存 6 个显式复形，
[oracle_corpus.json](../tests/fixtures/oracle_corpus.json)保存 77 份产品回归输入。
包含单形出生 stage、原尺度、坐标、正权、单位、算术、截断、来源/hash 及完整 corpus hash。
实际链构造和 GUDHI SimplexTree 均从同一单形列表导出；自动补面或修复过滤被拒绝。
GUDHI 显式使用 F2，核对最高请求次数所需 q+1 次单形、重复尺度和常量末端延拓。
一般 AD=0 窗口没有单形适配时明确 NotApplicable，不另造复形。

[输入测试](../tests/test_simplicial_inputs.py)、[GUDHI 测试](../tests/test_gudhi_oracle.py)
和[完整 corpus 回归](../tests/test_oracle_corpus.py)独立核对输入、拓扑、同 P 几何与恢复。
运行命令见 [VALIDATION](VALIDATION.md)。这些有限输入不证明一般规模效率或应用收益。

## Feature pairing migration

[feature_pairing.json](../tests/fixtures/feature_pairing.json) freezes a unit-weight
triangle stream with H0 merges, a finite H1 class, and infinite H0 survivors.
Its expected pairs were generated by `incremental.replay` from
`homology-operator-lab @ f4d0de6a8f1cd0285e4dda0a48d951b60dad3282`.
The source record includes original byte SHA256 for `verify.py`, `dynamic.py`
and `incremental.py`; `payload_sha256` binds canonical sorted compact JSON of
the raw stream and expected pairs. No research code is a runtime/test dependency.

[Family tests](../tests/test_family.py) compare both `EmptyInitial` (research
incremental, birth 1 after the first insertion) and `AfterInsertion` (research
dynamic, birth 0) numbering. Independent set-incidence windows, raw-boundary
coset enumeration and the existing PH oracle check complete historical bases,
all interval ranks and exact simplex endpoints. Random face-first tetrahedron
orders cover H0 through H3. Duplicate algebraic intervals, equal scales, infinite
deaths, empty homology, source/history/certificate forgery and portable JSON
recovery have separate regressions. These checks establish bounded correctness
evidence, not an incremental speed or general performance claim.

## Geometry query corpus T1 to T5

[geometry_queries.json](../tests/fixtures/geometry_queries.json) freezes exact
simplex streams, levels, degree, optional original geometry and a canonical
sorted compact JSON corpus SHA256. T1 is the six-edge K4/filled-face input
(the weighted 8/8/9 class minima remain in `reference.json`); T2 is the H1
square pair with explicit ties and threshold equality; T3 is the H2 tetrahedral
filling; T4 has duplicate numerical intervals and nonunique class minima; T5
retains source coordinates and original IDs in an exact embedded square fan.
These are synthetic, directly specified inputs, not copied molecular data.

The corpus records the fixed research revision and LF-normalized SHA256 for
`geometry_queries.py` from
`homology-operator-lab @ 4349866166962e25d515fa1cec1f0460e7f659a4`.
Production baseline main is `9c2c09f`; the local integration includes pending
PR #109 head `939a8edfd4adab945cf960f1b3d2bde83d3138e0`. This records an assumed
combined state, not an actual merge of #109.
[Independent set enumeration](../tests/oracle/geometry.py) imports no runtime
module. [Shared tests](../tests/test_stable_volume.py) compare 180 pair/stable
queries across both stage conventions, basis reversals and multiple epsilons,
along with class/birth queries, exact boundaries, supports, histories, real
GUDHI 3.11.0 F2 pairings, failures, tampering and restored records. Distinct legal
interval bases or tied representatives are compared in their own quotient
fibers, not forced to match raw-reduction chains.

HomCloud comparison pins the official 5.4.0 archive SHA256
`41a095599249cbc0092a835d6888eb252a6c4cd7935ac71481cd37e00f9e883b`
and `homcloud/optvol.py` SHA256
`99c7fbb305a5e34bc0356ef188fa828e35183ad00a001a01c79a87e025f9fcd3`.
The unchanged upstream Python optimizer runs with PuLP 3.3.0/CBC, using signed
continuous real LP variables. In the two-triangle unit-cost disk the shared-edge
equation is x1=x2 (or no equation), with death x2=1, so the optimum is integral
and the matched allowed sets have the same binary optimum. Epsilons 1/2 and
3/2 agree. Epsilon 1 retains a deliberate mismatch: HomCloud `bisect_right`
skips the equal-threshold row; Definition 6 retains it. This is source-function
LP replay, not compiled/public Pair integration or general integer equivalence.
